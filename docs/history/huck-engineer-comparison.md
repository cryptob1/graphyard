# Huck Engineer investigation: lessons for Graphyard

For a maintainer weighing a capability: what Graphyard adopted, and refused.

- **Prove behaviour through authoritative outcomes, not a green job:** [Evidence and proof authority](../protocol/evidence.md)
- **Distinguish unmeasured from failed:** The behaviour states in [validation](../validation.md)
- **Derive requirement satisfaction from evidence rather than a status field:** The acceptance gate in [architecture](../architecture.md)
- **Attribute each validation run to one target:** [Candidate-to-deployment attribution](../attribution.md)
- **Shared staging can make strict evidence impossible to finish:** The `shared-staging` target kind, granted only against a measured match
- **Reconcile release ranges, not only triggering commits:** Release membership in [observed production delivery](../delivery.md)
- **Observe what services actually run:** Observer registrations and measured identity
- **Diagnose why work is stuck:** `graphyard diagnose` and [flow analytics](../flow-analytics.md)
- **Preserve attempts and artifacts, and replay them with explicit coverage:** [Recovery](../recovery.md) and [evidence replay](../evidence-reuse.md)
