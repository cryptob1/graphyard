# Development and dogfooding

## Where a new feature goes

`AGENTS.md` text is generated by `src/repository-setup.ts`.

CLI `src/cli/`, routes `src/server/routes/`, rules `src/model/`, tables `src/store/tables/`, views `web/pages/`, protocol pages `docs/protocol/`.

## Validate a change

```sh
npm ci && npm run build && npm test
```

Worktrees need [bubblewrap](install.md#preconditions). CI's `test` aggregates shards balanced by file count and runs affected tests. Trusted CI runs only protected source: land a harness and `scripts/contracts.mjs` entry before requiring its proof.

### Verification maps

`verification/AREA.md` maps (store, server, master): a `Paths:` line of globs plus `## Tests`, `## Drive`, `## Invariants`, `## Gotchas`, ≤250 words each (tests/verification-maps.test.ts). 

### Base failures

A merge trial whose failing tests fail on the base tip too: no rework, no filed item; the writer holds the head (`base failure`) on one attention entry naming the test; retried on the then tip after 30 min.

## Documentation

`docs/README.md`, `docs/protocol.md`: generated in full from each page's `<!-- page: Section | order | summary -->` line by `npm run docs:check -- --write`; [`GRAPHYARD_GENERATED_FILES`](coordination.md#generated-files-and-speed) exempts them from the regression guard. One topic per page: a documented command exists, its links resolve, and the page stays current (`tests/docs-glossary.test.ts`, `scripts/check-docs.mjs`).

### Documentation that rarely conflicts

Conflicts only in `docs/**/*.md` get docs-sync, not rework: base merges in keeping both sides; on system-driven items the rework is the loop's round, due 10 minutes after the conflict's first record.

`src/interventions.ts` only re-exports per-concern modules under `src/interventions/`: append a self-contained rule, never reword shared sentences.
