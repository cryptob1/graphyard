# Master-agent sessions

`master worker add FILE`, `master reviewer add FILE`; `master producer replace|remove` applies next tick; `master status` `sessions` lists handles.

## Approval modes

[`"approvals": "auto"`](onboarding.md#agent-environments) adds per-runtime unattended flags: Claude Code `--permission-mode bypassPermissions`; Codex `--ask-for-approval never --sandbox workspace-write`; opencode `OPENCODE_PERMISSION`; others likewise; Pi none. A worker launch derives opencode's document from the checkout it serves (GY-2959): the repository tree — `<repository>/**` and `<repository>/.graphyard/**` — is granted so a second worktree beside the assigned one never prompts, and everything outside the repository is denied; a profile's own document lays over it. Never started: `"prompt"`, `refusedLaunchKinds`, runtimes without command-line requests; [registry](onboarding.md#configure-the-fleet) runtimes need `{request}`.

## The coordinator checkout is confined at the OS level

Every launched role (worker, reviewer, producer, approver, spec checker and master), including Codex and registered runtimes, carries an outer bubblewrap namespace. The host root is read-only; an unavailable namespace refuses the launch. Hosts require `/usr/bin/python3` and Linux Landlock ABI 9 or newer for socket confinement; an unsupported host refuses execution before starting agent commands.

Outer merge-trial install, build, test and E2E commands run in disposable Docker containers built by `install` from the Dockerfile's `trial` target (`graphyard-trial:local`). Preview installation changes with `install --plan`. The image has a read-only private root, nonroot user, no capabilities, no-new-privileges, private PID/network namespaces and private temporary filesystems. Only allocated checkout/home/scratch directories are writable; required Git objects, shared dependencies and the trusted E2E harness are read-only mounts. Linked dependencies share one mount per destination; an explicit writable allocation takes precedence. Neither host root, operator home nor host command sockets are mounted. Host mise directory settings remain available to launcher tooling, while candidate commands use the image’s Node/npm toolchain and allocation-owned npm and browser caches. Serve commands and E2E clients run together on private loopback. For Compose-backed bound cases, the trusted launcher validates and starts the bounded stack; checkout binds, file secrets and configs become copied container content, with no host bind mounts, custom host drivers or added privileges. Case commands run in a private-root container sharing only the HTTP service’s private network namespace. They receive neither a Docker client nor an engine socket. The launcher removes the stack and its volumes/networks after passing or failing cases. Nested candidate tests assert that orchestration remains unavailable to them; the host regression exercises a real Compose stack. The image includes the locked Playwright Chromium build and its system libraries. Containers are removed when commands finish or are cancelled; a separate supervisor watches launcher lifetime through a pipe and removes the named container even after SIGKILL or output overflow, before releasing captured output pipes.

The outer container inherits no host filesystem Landlock domain: Linux forbids descendant mounts after that restriction. Tests can therefore establish nested bubblewrap mounts and then apply their own Landlock policy. Nested trial fixtures reconstruct a private root from the container toolchain and explicit allocations without requesting a host Docker socket. Ordinary host agent sessions retain mount-plus-Landlock confinement. Docker's seccomp profile is disabled for the trial's unprivileged user-namespace mounts; capabilities stay empty and privileged mode is never used.

### Worker sandbox

Confined Codex launches use `--sandbox danger-full-access` inside Graphyard’s already established mount and socket boundary. This selects no second runtime sandbox: Landlock denies subsequent mounts, so nesting Codex’s bubblewrap would prevent every shell command. Standalone sandbox probes retain the native workspace policy; confined probes exercise Codex under the outer boundary. The OS writable grants and credential masks remain enforced for every command.

Codex `--add-dir` roots: the common `.git` (GY-2977: `packed-refs` lock), `.git/worktrees/NAME`, `objects`, `refs/remotes`, `refs/heads/graphyard`, `logs/`.

The read-only mount re-exposes the common `.git` directory writable (GY-2967): every ref transaction a worker runs — commit, merge, reset, `branch -f`, `update-ref`, a cherry-pick's cleanup — takes the common `packed-refs` lock once anything has packed a ref (git gc does), and rewrites that file under the lock. Each runtime's own sandbox (Codex `--add-dir`, and the equivalent for other runtimes) must grant that common directory too (GY-2977): GY-2967 fixed only the bubblewrap layer, and a nested Codex sandbox that omitted it still refused `packed-refs.lock` with EROFS. Inside the mount, the checkout's own state is re-bound read-only — `index`, `HEAD`, `config`, `hooks`, the refs outside `refs/heads/graphyard`, and the shared `worktrees` area for a session with its own worktree admin — where the read-only bind still lets git take its `.lock` (the directory stays writable) but refuses the write and the rename that commits it, so the coordinator's index, HEAD, config and the base branch keep the protection they had.

### Host writes and scratch cleanup (GY-3045)

`master start codex` and `master start claude` explicitly retain their existing login directory: inherited `CODEX_HOME` or `CLAUDE_CONFIG_DIR`, otherwise `~/.codex` or `~/.claude`. Only that runtime directory is writable; the operator HOME stays read-only and the session HOME uses private scratch.

After establishing host-session mounts, the launcher applies an inherited Landlock socket policy before executing any runtime command. Pathname Unix sockets resolve only inside allocated writable directories, private scratch, or the existing filtered keyring proxy. Undeclared host sockets elsewhere are denied even when published after launch or reached through a symlink inside the worktree. Host abstract Unix sockets are also denied; local IPC created by the session remains available. This policy uses `LANDLOCK_ACCESS_FS_RESOLVE_UNIX` and `LANDLOCK_SCOPE_ABSTRACT_UNIX_SOCKET` ([kernel documentation](https://docs.kernel.org/userspace-api/landlock.html)); a read-only mount alone does not prevent socket connections. Ordinary TCP networking remains available, subject to the declared host-executor refusal below.

Writable host paths are the allocated worktree or session checkout, its required Git state described above, the explicitly assigned verification-slot directory, its own runtime login/binding directories and private scratch. The master also keeps its managed `.graphyard` state and explicitly supplied coordinator state directory writable. Merge trials grant only their allocated checkout/session and temporary directories, never the coordinator root. Trial HOME uses a separate short allocation beside trial scratch so nested Unix socket paths fit; npm and Playwright browser caches live beneath it; dashboard checks install Chromium there even when the host cache is empty or a host cache override is set. These caches are removed with the trial. Other host-home and unrelated-project files stay read-only in host sessions and absent in outer trials. The OS denies these writes without an approval prompt; routine work and existing delivery gates stay unattended.

Each agent's `.graphyard/scratch` is mounted at `/tmp` and `/var/tmp` inside its namespace. Outer trials use private temporary filesystems there and bind their allocated disk scratch at its own path. These short paths stay on the allocated disk so checks can create Git fixtures and Unix sockets. `TMPDIR`, `TMP` and `TEMP` point there; trials preserve their short allocated temporary path so nested checks and cleanup retain its identity. HOME, runtime scratch and caches also live there. Explicit runtime login homes remain available, including accounts whose login variable is `HOME` or `XDG_CACHE_HOME`: an environment value pointing into an explicitly granted writable directory is preserved. Headless confinement uses the same effective environment as the child, including registry and per-run overrides, to mask Unix command endpoints and refuse remote ones. A refused merge trial releases its allocated checkout and temporary directories. `/dev` is a fresh minimal device filesystem. Host `/run`, host temporary directories, Docker runtime directories, and Herdr session directories and configured Unix Docker/Podman/BuildKit/SSH/Herdr endpoints are hidden; systemd buses stay masked (only the existing filtered keyring proxy may be re-exposed).

Create scratch with `scratch=$(mktemp -d)` in the session, keep that variable in the same shell, and clean only that directory after checking its value. Never use `HOME=$(mktemp -d) command; rm -rf "$HOME"`: the assignment affects only `command`, and the later expansion uses the parent HOME. After an incident, stop the command and inspect the exact allocated directory; never clean the operator HOME or infer a cleanup target from a missing CLI. Session checkout cleanup removes its scratch. `e2e/cases/worker-filesystem-isolation.json` runs the real namespace regression: disposable host-home sentinels, all roles, normal work, the command-scope mistake and host control sockets.

Declared host-control endpoints (`DOCKER_HOST`, `CONTAINER_HOST`, `BUILDKIT_HOST`) must use local `unix:///` sockets, which are masked. A TCP, SSH or other remote endpoint refuses the launch automatically before any command starts: mount isolation cannot constrain a host executor reached over the network. Ordinary network access remains available. Registered master runtimes keep only their configured account home directory writable, including a custom `homeVariable`; sibling account directories remain read-only.

### Credentials are hidden from confined sessions (GY-1856)

Read-only checkout confinement is not credential isolation, so the mount also masks the operator's credential locations with an empty tmpfs: the whole config home (`~/.config/graphyard`, or `GRAPHYARD_CONFIG_HOME`) — every install, master, worker, reviewer and producer directory under it — plus each credential path the install records beside it (the coordinator credential, `run.mergeWriter.deployKeyFile`, `upstream.credentialFile`) and the per-install `confinement.maskPaths` list in `.graphyard/master.json` for anything else (a collector's token file, say). A recorded path is masked at the nearest directory that holds it; a stale path hides nothing. Only the session's own credential survives: its token file (the one `GRAPHYARD_TOKEN_FILE` names, re-exposed read-only), a reviewer's or spec checker's binding directory (`reviewers/sessions/<id>`, its `GH_CONFIG_DIR`, re-exposed writable), and its runtime login home (the value its launch sets on the runtime's home variable, re-exposed writable), so `git status`, `git commit`, `graphyard sync` and the repository's test command keep working in its worktree. The mask applies to every session launched inside the wrapper — workers, reviewers, producers — each keeping its own credential; the master session, which acts as the coordinator identity, keeps its coordinator credential.

An install deployed under its own config home runs its CLI from there too (`<install>/deploy/build/bin/graphyard.mjs`), so the mask keeps that deploy checkout readable — read-only, code only — with the session's own paths (GY-2995): a confined reviewer or spec checker can execute the CLI its prompt names and post its verdict, while every credential beside the checkout stays unreadable. A review or spec-check launch whose sandbox still cannot reach the CLI its prompt names is refused before any session starts: `master status` names the launcher and the fix as configuration attention, and the loop waits instead of relaunching (a restored CLI launches again on its own).

Launches take the first account under `run.quotaCeilingPercent`, else fail over; limit notices hold the account (`capacity.exhausted`), among them Z.AI's 429 `Rate limit reached` envelope (`{"code":"1302",…}`), which names no reset and holds its account 15 minutes, and Claude's `You've hit your session limit · resets 1:30am (America/Los_Angeles)` and `You've reached your Fable limit. …` (GY-2962): the session limit holds until the reset it names, a session or usage limit with no readable reset holds 6 hours, and a Fable limit — which names no reset — until the next 08:00 local. Concurrent launches spread across provider plans before any plan takes a second live session, so one plan's limit cannot take the fleet down. Reviewers/producers: profile `kind` only. A rework worktree starts from the submission head in the shared object store, pushing no worker branch.

## The loop's own master session

`master registry role set master ACCOUNTS …`: one session; loop and `master start` adopt live `masterAgentName`. Relaunched once gone from Herdr. `master registry propose` proposes the master role beside the others — the reviewer's accounts, concurrency 1 — so a fresh install's loop launches its own session; renaming the role's accounts replaces that proposal.

### A pane stopped on its provider's limit is absent (GY-2949)

Each cycle reads the master pane's recent output with the same limit-notice judge workers use. A usage or session limit notice (`You've hit your session limit · resets 1:30am`) is treated as absent: the account is held until the parsed reset (the hold rides every selection, so the spent plan is not asked again), the pane closes, and the role's next account launches the master in the same cycle. Exited panes relaunch without a hold. `master status` shows the session's state on its one page: `working`, `idle` (Herdr reports the pane idle), `limited until T` while the hold stands, and `absent` once the pane is closed with no hold standing.

### A closed Herdr workspace is replaced

Each cycle checks `herdrWorkspace` against `herdr workspace list`, as does the next reload after any launch refused with `workspace_not_found`. A missing workspace is replaced in `.graphyard/master.json` by `masterAgentName`’s workspace (else the first listed), recorded as a `config` action; blocked dispatches unblock.

### The request is the session's first message

#### How the request reaches the runtime

Written to `.graphyard/launch/NAME.request` (Claude also `NAME.role`), 0600, removed with the checkout; the typed line is bounded at **512 bytes**:

```
claude … --settings …/.graphyard/harness/ROLE.json --append-system-prompt-file "$GY.role" "$(cat "$GY.request")"
```

#### The start bound reads the pane

**Ready**: Herdr active without prompt, or banner shown (`the claude runtime is on screen while Herdr reports it unknown`). Ready within **60 seconds** (`run.launchStartSeconds`) starts; starting gets **120 seconds** (`started.extended`). Refusals quote case and pane's last non-empty line, never Herdr's own `agent_not_found`.

#### First-run consent prompts

**`awaiting consent`**: answers only `hooks-continue-untrusted` (**Continue without trusting**), `telemetry-decline`, never one that grants hook execution or a sandbox escape; others (**credential**, **payment**) wait for the human. Held: `.graphyard/launch/NAME.consent` (`herdr pane attach`); after **15 minutes** the supervisor stops renewing; the item dispatches.

Reviewers/producers are `awaiting acknowledgement` until 30s active, re-prompted once quiet past `run.acknowledgementSeconds` (90); resultless is **`never started`**: relaunched ≤3 times (`retry.neverStarted`), [then elsewhere](master-agent-reference.md#producer-runtime-faults).

**Worker stall** (`run.inactivityMinutes`, 10): a worker session Herdr reports idle with no recorded activity for the window is re-prompted once with its own work; still idle a whole window after that re-prompt, the close step ends it as **`stalled`**: the pane closes, the attempt releases with its lease (a provider limit notice on the pane holds its account — Z.AI's 429 envelope for 15 minutes), and the item dispatches again next cycle. A session that has stopped, whose pane's last lines already carry a recognised limit notice — Claude's `You've reached your Fable limit. …` or `You've hit your session limit` among them — ends at once on it, with no window waited and no re-prompt: the attempt ends as a limit, the lease releases, and the account is held for the notice's reset (GY-2962).

**Blocked on its runtime's own prompt** (GY-2959): a worker Herdr reports `blocked` is answered by the close step, not renewed under — the loop reads the prompt off the pane and sends its reject key once (OpenCode's external-directory Allow once / Always allow / Reject chooses Reject, which leaves the worker inside its worktree; a destructive command's No is declined the same way); one still blocked a whole window after the answer ends as **`stalled`** naming the prompt text, lease released, item dispatchable. One that unblocked after the key is left alone, and a new prompt gets a fresh answer. The launch instruction names the external-directory prompt beside the rm/mv one, and the worker launch pre-grants the repository tree so the prompt does not appear for a worktree beside the assigned one.

**The next attempt resumes the last one's session** (GY-2971): a Claude Code worker launches with `--session-id ID`, and the item's launch record (`.graphyard/dispatch/dispatched-KEY.json`) keeps the id with its runtime, account and worktree. The item's next attempt or rework round — on the same runtime and account — launches `claude --resume ID` in its own worktree under its own epoch, its complete brief (head, findings, rework reason) still the first request; only the conversation carries over. Another runtime, an account the selection passed over (limited, logged out), no recorded id, or a resume that fails its start bound launches fresh as before, logging `attempt N launches a fresh session: WHY`; a failed resume relaunches the same attempt under the lease it holds. `master status` reads `attempt N (resumed from M)`. Measure it by each item's `pipeline.attempts` count and `pipeline.reworkRounds`:

| Measure | Read from |
|---|---|
| attempts per item | `pipeline.attempts.length` |
| rework rounds | `pipeline.reworkRounds` |

**Reviewer verdict**: every review launches on the control plane under the profile’s agent identity; no reviewer GitHub App, installation or private key is configured. `master reviewer add|remove` manages launch profiles. Launch writes `review-binding.json` (0600: head, base, policy revision; `verdictToken`, `previousHead`) into `GH_CONFIG_DIR`; no binding, no session. Verdicts post once via `graphyard review post --event …`; refused on a moved head. **Self-review**: before `complete`, workers run `graphyard review self GY-N`.

**Registry slot**: the launch's agent-registry session rides its ledger record; the loop's close step ends it once the verdict is recorded, the item leaves review, or the pane is gone from Herdr (the reason names the pane), so a finished review or proof stops consuming its role's concurrency. Producers likewise. A session whose launching loop restarted away has no handle the successor loop tracks; each dispatch tick also judges every registry session the control plane lists live for this host by the pane its ledger record names, and ends it on the second consecutive miss.

**The attempt bound is a progress bound** (GY-2961): an attempt whose worktree shows a new commit or changed files within the last 20 minutes, and whose lease renews, runs past the bound and is stopped only at the **ceiling** (default 8h); one with neither is stopped at the **bound** (default 130min since the claim). Each cycle the loop reads the attempt's worktree and records what changed on the session handle, so the control plane's renewal refusal counts the same progress. The stop keeps the attempt's uncommitted work as one WIP commit on its branch — a successor receives the diff — and releases the lease. The launch brief names the end instant, the rule and the ceiling (`run.attemptBoundMinutes` / `run.attemptCeilingMinutes` set both per install), and `master status` shows each live attempt's remaining time. **Unsubmitted past the bound** (lease 60min): `unsubmitted-attempt` shown; from 130min renewal refused as the backstop when no progress of either kind is on the record. Open scope asks exempt.

### One continuing master conversation

Claude and Codex masters resume their current native conversation on the same account/runtime. Another account/runtime starts a successor: its request names the predecessor's runtime, account, native id, full read-only transcript and last unanswered person input (explicitly `none` when answered). A→B→A continues B: successors supersede predecessors. Failed launches retain the conversation; native resumes never fall back fresh. Unsupported master runtimes refuse explicitly. Across repeated failovers, an unanswered input keeps its native-event reference.

`master.continuity` persists current/predecessor identities independently of registry allocations. `.graphyard/master-records/` holds full native transcripts, mounted read-only without granting another account home or credentials. `.graphyard/launch/LAUNCH.inputs.jsonl` records launch/wake/retry origins before submission, joined to native input events by unique markers. Tools and partial output never answer a person; a completed assistant final after the input batch does. Pre-upgrade/adopted sessions recover native records from their recorded account and import known delivery origins; failed recovery retains state and retries each cycle, with one standing diagnostic per unchanged failure. A live master still receives deduplicated incidents and bounded heartbeats while recovery fails; their marked origins survive later adoption. Replacement and failover wait for continuity recovery. Native JSONL is scanned one row at a time and copied byte-for-byte into read-only records, including transcripts larger than 2 GiB.

`master-large-transcript-wake` covers the size boundary and live recovery failures. A failed transcript read leaves the previous retained record intact; recovery retries after its source is repaired. `master-session-resumes` and `master-continues-after-failover` run fixtures with user-only Claude settings under bubblewrap, inspecting records and transcript confinement.
