# Turnkey E2E execution and verified delivery

For a reader asking what comes next: which completion profile a delivery may claim.

## Product promise and boundary

A repository without tests needs scenarios and executable assertions first: a planning agent may propose them, but Graphyard never manufactures passing evidence or presents inferred criteria as verified requirements.

- **Through merge:** A verified, authorized merge completes the configured workflow
- **Preview validation:** A pinned preview artifact plus required behavioural proof
- **Production verification:** Expected artifacts independently observed across required production services, with required checks passing

## Increments

D1 to D6 ship the invariants stated by [validation](validation.md), [runner setup](runner-setup.md), [delivery](delivery.md) — model and protocol only — [recovery](recovery.md), [report adapters](report-adapters.md) and [evidence reuse](evidence-reuse.md). Deployment-provider adapters are excluded, so production verification stays a manual proof.
