Graphyard · how it works

From a goal to production, run by agents

You state what you want. Graphyard breaks it into small work items, has AI agents build, test and review each one, merges what passes, and verifies it on the live release. People decide the goals; agents do the rest and check each other.

The path of one goal

flowchart LR
  A[Goal] --> B[Planner splits it into work items]
  B --> C[Worker builds an item]
  C --> D[Graphyard tests the merged result]
  D --> E{Risky change?}
  E -- yes --> R1[Review first] --> F[Graphyard merges to main]
  E -- no --> F
  F --> R2[Review after merge]
  F --> G[Release candidate: UAT + end-to-end tests]
  G --> H[Promoted to production]
  H --> I[Verified on the live release]
  G -. failure .-> J[Revert or new fix item]
  J --> C

  1. State a goal

    A short plain-language file: what to build, for whom, any constraints, and where it ships.

  2. Plan it into work items

    A planner agent turns the goal into small items like GY-1772, each with acceptance criteria and the tests that prove them.

  3. Build

    The master loop hands each ready item to a worker agent in its own workspace. Low-risk changes go to cheap fast runtimes (Pi) first; risky or repeatedly reworked ones go to stronger models.

  4. Test the merged result

    Graphyard tests the change as it would land on the latest main, not the branch alone, using the build, unit tests and each criterion's proof tests.

  5. Review

    An independent agent reviews it. Sensitive changes (auth, data, deploy, CI) are reviewed before merge; normal ones after. A reviewer never reviews its own work.

  6. Merge

    Graphyard itself writes main. Nothing merges with a failed check, an open blocking finding or an unapproved decision.

  7. Release and verify

    Merged changes ride a release candidate through UAT and the end-to-end suite, are promoted to production, and are checked on the exact release that serves them.

  8. Recover

    A failure anywhere is reverted or fixed forward by a new work item. The loop keeps cycling until every item is verified live or has a real external blocker recorded.

Who does what

Master loop

Runs every ~20 seconds: dispatch, review, merge, deploy checks, cleanup. Upgrades itself when a new release is live.

Master agent

Reads the loop's state, files and releases work, and handles what the loop can't settle by rule.

Workers

Build one item each, under a lease they renew; losing the lease means they stop.

Reviewers

Judge each change against its criteria. Always independent of whoever built it.

Approvers

Sign off on decisions the master requests: requirement changes, scope widenings, risky reworks.

Control plane

The server that holds every item, lease, decision and piece of evidence, with full history.

What people decide

Everything else is decided by one agent and approved by a different one. People keep exactly three decisions:

  • Goals and priorities
  • Spending money or opening third-party accounts
  • Issuing credentials to people

What every item must pass

GatePasses when
ReadyReleased, dependencies done, no open blocker.
BuildA worker submitted a head inside the item's planned files.
ReviewAn independent reviewer approved this exact head (before or after merge, by risk).
TestRequired checks and every criterion's proof passed on the merged result.
MergeGraphyard landed it on main and confirmed main holds it.

Requirements are never weakened to let an implementation pass, and agents never get the credentials that produce trusted evidence.

When is it actually done?

Merged→ Awaiting deployment→ Deployed→ Production verified

Merged code is not shipped code. An item counts as delivered only when the release serving production contains it and it has been checked there.

When something gets stuck

The loop notices its own problems: slow cycles, failing steps, flaky tests, false reverts. Known failures have a built-in fix the loop applies itself; anything else goes to the master agent, and anything that is a defect in Graphyard becomes a work item that agents fix. The aim is that nobody has to step in by hand.
